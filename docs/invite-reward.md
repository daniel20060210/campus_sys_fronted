# 邀请有奖业务文档

## 1. 业务概述

邀请有奖是校园食堂平台推出的用户拉新活动，允许管理员创建邀请有奖活动，通过奖励机制激励现有用户邀请新用户注册。

**核心特点：**
- 多活动模式：可以同时创建多个邀请有奖活动
- 分层奖励：根据邀请人数设置不同档位的奖励
- 奖励类型：支持现金和优惠券两种奖励形式
- 邀请追踪：记录每个邀请人和被邀请人的关系及行为

## 3. 业务流程

### 3.1 活动生命周期

```
[创建活动] → [设置奖励层级] → [开始活动] → [邀请进行] → [结束活动] → [活动结束]
     ↓            ↓              ↓            ↓            ↓
   未开始       未开始       进行中       进行中        已结束
```

**状态流转：**

1. **未开始**：管理员可以编辑活动信息、管理奖励层级
2. **进行中**：
   - 活动开始时间已到达，管理员点击"开始活动"按钮
   - 用户可以生成邀请链接进行邀请
   - 管理员可以查看邀请记录
   - 奖励层级管理禁用（防止活动期间规则变化）
3. **已结束**：
   - 管理员点击"结束活动"按钮，或活动结束时间到达
   - 用户无法再通过此活动邀请
   - 所有管理功能禁用

### 3.2 邀请奖励流程

```
用户A生成邀请链接
       ↓
用户B通过邀请链接注册
       ↓
用户B完成 首单/实名/等条件
       ↓
系统统计用户A邀请的人数
       ↓
用户A获得对应层级的奖励
```

**奖励发放规则：**

1. 按被邀请人完成注册的时间先后计算
2. 达到层级门槛后自动发放对应奖励
3. 现金直接发放到用户账户
4. 优惠券发放到用户优惠券账户

### 3.3 用户视角

1. 用户进入"邀请有奖"活动页面
2. 查看活动详情和奖励规则
3. 生成个人邀请链接/二维码
4. 分享给好友
5. 好友通过链接注册并完成首单
6. 查看邀请进度和已获得奖励

## 4. 业务规则

### 4.1 活动规则

- 可以同时存在多个邀请有奖活动（不同时间周期的活动）
- 活动未开始时，管理员可以设置奖励层级
- 活动进行中，层级管理功能禁用
- 活动结束后，所有数据只读
- 活动开始后，系统自动将开始时间更新为实际开始时间

### 4.2 奖励层级规则

- 每个活动至少需要一个奖励层级
- 邀请人数必须递增（如：3人→5人→10人）
- 奖励金额建议递增（邀请更多人应获得更多奖励）
- 奖励类型可以混合（部分现金、部分优惠券）
- 活动进行中禁止修改层级

### 4.3 奖励预算规则

- 奖励预算为活动期间计划发放的奖励总额
- 已使用奖励不能超过奖励预算
- 预算用完后不再发放奖励（需要管理员追加预算或结束活动）

### 4.4 邀请关系规则

- 一个用户可以邀请多个被邀请人
- 每个被邀请人只能对应一个邀请人
- 被邀请人首次注册时绑定邀请关系
- 邀请关系一旦建立不可变更

## 7. 典型使用场景

### 场景一：创建新活动

1. 管理员进入"邀请有奖"页面
2. 点击"编辑活动"，创建新活动
3. 设置活动名称、描述、时间、预算
4. 点击"添加层级"，设置奖励规则（如：邀请3人得10元）
5. 设置多个层级（3人、5人、10人等）
6. 完成后，点击"开始活动"

### 场景二：查看邀请数据

1. 管理员进入活动页面
2. 查看统计数据（邀请人数、预算使用等）
3. 查看奖励层级是否需要调整
4. 查看邀请记录，了解用户邀请情况
5. 可按昵称或学校搜索特定用户

### 场景三：结束活动

1. 活动到期或需要提前结束
2. 点击"结束活动"按钮
3. 系统提示确认
4. 确认后活动状态变为"已结束"
5. 所有管理功能禁用

## 10. 注意事项

1. **层级递增**：奖励层级的人數要求必须递增（如3→5→10）
2. **预算控制**：已发放奖励接近预算时注意监控
3. **结束保护**：活动结束后层级管理禁用，防止误操作
4. **邀请关系**：一旦绑定不可变更，删除活动需谨慎
5. **数据隔离**：多活动时确保统计数据按活动分别统计
6. **奖励类型**：现金和优惠券有不同的使用场景和有效期
